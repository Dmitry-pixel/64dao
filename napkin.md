
## SEO / Next.js Gotchas

1. **[2026-07-06] Динамический сегмент [slug] без generateStaticParams → force-dynamic → no-store**
   Do instead: добавить `generateStaticParams()` в `page.tsx` для `/documents/[slug]` (и любых будущих `[param]`-роутов) — иначе Cache-Control: private/no-store, нестабильный ответ под краулерами (воспроизведено: Google Rich Results Test — Crawl failed до фикса, valid item после).

2. **[2026-07-06] JSON-LD в Next.js App Router**
   Do instead: `<script type="application/ld+json" dangerouslySetInnerHTML={{__html: JSON.stringify(data)}} />` без `<head>` — рендерится в body корректно. Компонент `frontend/components/JsonLd.tsx`, переиспользуется на всех страницах.
3. **[2026-07-28] Контент за useState не попадает в SSR-HTML — краулеры его не видят**
   Симптом: `FaqSection` рендерил ответ только при `openIndex === i`; в серверном HTML были одни вопросы, ответов не было. AEO-чекер и Google Rich Results FAQ не находили (воспроизведено: `curl -s / | grep -c "<текст ответа>"` → 0 до фикса, 2 после — видимая разметка + JSON-LD).
   Do instead: аккордеоны строить на `<details>/<summary>` без клиентского состояния — секция остаётся серверной, ответ всегда в HTML. Вопрос класть в `<h3>` внутри `<summary>`, не в `<button>` (в button нельзя ни `<h3>`, ни `<p>` — невалидная вложенность). Маркер убирать через `list-style:none` + `::-webkit-details-marker{display:none}`.
   Тексты выносить в общий модуль (`frontend/lib/faqData.ts`) и из него же собирать JSON-LD: если разметка и схема расходятся, Google отбрасывает схему как неподтверждённую видимым контентом.

4. **[2026-07-28] Серверная страница с вложенным `SiteFooter` не бывает чистой статикой**
   Симптом: `/method` и `/method/[slug]` прегенерированы (`○`/`●` в таблице сборки), но отдают `Cache-Control: s-maxage=60, stale-while-revalidate`, а не иммутабельную статику. Причина — `SiteFooter` тянет `/api/social-links` с `next: { revalidate: 60 }`, и роут наследует минимальный revalidate среди своих fetch.
   Do instead: для индексации это безвредно — `private`/`no-store` не появляется, краулер страницу видит. Если нужна чистая статика, верстать подвал раздела без `SiteFooter`. Не пытаться лечить заголовками nginx: причина в графе fetch, а не в прокси.

5. **[2026-07-28] Консоль FastPanel детерминированно портит один символ в строке длиной 6000**
   Симптом: пять base64-кусков по 6000 символов, `wc -c` совпал на каждом шаге (6001/12002/18003/24004/24313), но md5 собранного архива не сошёлся. Подмена символа длину не меняет, поэтому по `wc -c` брак не ловится. Повторная вставка того же куска дала тот же битый md5 — искажение воспроизводимое, не случайный шум. Куски по 3000 символов проходят чисто.
   Do instead: резать base64 по 3000 символов и после каждой вставки проверять построчный md5: `while read -r l; do printf '%s' "$l" | md5sum; done < файл`. Эталоны считать заранее: `printf '%s' "$(cat part.txt)" | md5sum`. Битую строку менять точечно — `sed -n '1,2p'` и `sed -n '4,5p'` в отдельные файлы, новую строку между ними, затем `cat` обратно.

6. **[2026-07-28] Проверка прода: только curl с сервера, и не через `grep -c`**
   Симптом: внешний загрузчик страниц отдал закэшированный `robots.txt` без секций для цитирующих агентов — расхождение с исходником оказалось мнимым, на поиск несуществующего дефекта в nginx и Docker ушло около десяти шагов. Отдельно: `curl -s /method | grep -c 'href="/#'` вернул 1 при четырёх ссылках, потому что HTML минифицирован в одну строку.
   Do instead: внешние проверки делать `curl` с сервера, заголовки — `curl -sI`. Совпадения в HTML считать `grep -o ... | wc -l`, не `grep -c`. Перед выводом «прод отстал от исходника» сверяться с `curl http://127.0.0.1:3000` — если локально верно, а снаружи нет, только тогда искать прокси и кэш.
7. **[2026-07-28] `sed` по шаблону `allow:` попадает в хвост `disallow:`**
   Симптом: `sed -i "s|allow: '/',|allow: PUBLIC_PATHS,|g"` в `robots.ts` заменил и `disallow: '/',` → `disallow: PUBLIC_PATHS,`; правило для обучающих краулеров перестало означать «запретить всё». Второй `sed -i "3a ..."` продублировал константу, потому что файл уже содержал целевую версию.
   Do instead: `robots.ts` и подобные короткие файлы править heredoc'ом в `/tmp` плюс `diff -u` перед `cp`. Перед любым `sed -i` смотреть текущее состояние через `grep -n`. Откат — `git checkout -- файл` и повторный `cp` из `/tmp`.
8. **[2026-07-28] Прод собирается в Docker; правка на хосте не видна без пересборки**
   Симптом: `frontend/.next` на хосте отсутствует, `find / -name robots.txt` находит файл только в слоях overlayfs. `robots.txt` в `.next/server/app/` — это директория с `route.js`, `cat` по ней даёт «Is a directory», и пустой вывод легко принять за отсутствие маршрута.
   Do instead: деплой — `docker compose build frontend && docker compose up -d frontend`. Сервисы `db`, `backend`, `frontend`; контейнер `dao64_frontend`, порт 127.0.0.1:3000. `robots.txt` и `sitemap.xml` генерируются из `src/app/robots.ts` и `src/app/sitemap.ts`; в `public/` из текстовых файлов только `llms.txt`.
