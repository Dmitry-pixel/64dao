1. **[2026-07-06] Динамический сегмент [slug] без generateStaticParams → force-dynamic → no-store**
   Do instead: добавить `generateStaticParams()` в `page.tsx` для `/documents/[slug]` (и любых будущих `[param]`-роутов) — иначе Cache-Control: private/no-store, нестабильный ответ под краулерами (воспроизведено: Google Rich Results Test — Crawl failed до фикса, valid item после).

2. **[2026-07-06] JSON-LD в Next.js App Router**
   Do instead: `<script type="application/ld+json" dangerouslySetInnerHTML={{__html: JSON.stringify(data)}} />` без `<head>` — рендерится в body корректно. Компонент `frontend/components/JsonLd.tsx`, переиспользуется на всех страницах.
3. **[2026-07-28] Контент за useState не попадает в SSR-HTML — краулеры его не видят**
   Симптом: `FaqSection` рендерил ответ только при `openIndex === i`; в серверном HTML были одни вопросы, ответов не было. AEO-чекер и Google Rich Results FAQ не находили (воспроизведено: `curl -s / | grep -c "<текст ответа>"` → 0 до фикса, 2 после — видимая разметка + JSON-LD).
   Do instead: аккордеоны строить на `<details>/<summary>` без клиентского состояния — секция остаётся серверной, ответ всегда в HTML. Вопрос класть в `<h3>` внутри `<summary>`, не в `<button>` (в button нельзя ни `<h3>`, ни `<p>` — невалидная вложенность). Маркер убирать через `list-style:none` + `::-webkit-details-marker{display:none}`.
   Тексты выносить в общий модуль (`frontend/lib/faqData.ts`) и из него же собирать JSON-LD: если разметка и схема расходятся, Google отбрасывает схему как неподтверждённую видимым контентом.

4. **[2026-07-28] Серверная страница с вложенным `SiteFooter` не бывает чистой статикой**
   Симптом: `/method` и `/method/[slug]` прегенерированы (`○`/`●` в таблице сборки), но отдают `Cache-Control: s-maxage=60, stale-while-revalidate`, а не иммутабельную статику. Причина — `SiteFooter` тянет `/api/social-links` с `next: { revalidate: 60 }`, и роут наследует минимальный revalidate среди своих fetch.
   Do instead: для индексации это безвредно — `private`/`no-store` не появляется, краулер страницу видит. Если нужна чистая статика, верстать подвал раздела без `SiteFooter`. Не пытаться лечить заголовками nginx: причина в графе fetch, а не в прокси.

5. **[2026-07-28] Консоль FastPanel детерминированно портит один символ в строке длиной 6000**
   Симптом: пять base64-кусков по 6000 символов, `wc -c` совпал на каждом шаге (6001/12002/18003/24004/24313), но md5 собранного архива не сошёлся. Подмена символа длину не меняет, поэтому по `wc -c` брак не ловится. Повторная вставка того же куска дала тот же битый md5 — искажение воспроизводимое, не случайный шум. Куски по 3000 символов проходят чисто.
   Do instead: резать base64 по 3000 символов и после каждой вставки проверять построчный md5: `while read -r l; do printf '%s' "$l" | md5sum; done < файл`. Эталоны считать заранее: `printf '%s' "$(cat part.txt)" | md5sum`. Битую строку менять точечно — `sed -n '1,2p'` и `sed -n '4,5p'` в отдельные файлы, новую строку между ними, затем `cat` обратно.

6. **[2026-07-28] Проверка прода: только curl с сервера, и не через `grep -c`**
   Симптом: внешний загрузчик страниц отдал закэшированный `robots.txt` без секций для цитирующих агентов — расхождение с исходником оказалось мнимым, на поиск несуществующего дефекта в nginx и Docker ушло около десяти шагов. Отдельно: `curl -s /method | grep -c 'href="/#'` вернул 1 при четырёх ссылках, потому что HTML минифицирован в одну строку.
   Do instead: внешние проверки делать `curl` с сервера, заголовки — `curl -sI`. Совпадения в HTML считать `grep -o ... | wc -l`, не `grep -c`. Перед выводом «прод отстал от исходника» сверяться с `curl http://127.0.0.1:3000` — если локально верно, а снаружи нет, только тогда искать прокси и кэш.
7. **[2026-07-28] `sed` по шаблону `allow:` попадает в хвост `disallow:`**
   Симптом: `sed -i "s|allow: '/',|allow: PUBLIC_PATHS,|g"` в `robots.ts` заменил и `disallow: '/',` → `disallow: PUBLIC_PATHS,`; правило для обучающих краулеров перестало означать «запретить всё». Второй `sed -i "3a ..."` продублировал константу, потому что файл уже содержал целевую версию.
   Do instead: `robots.ts` и подобные короткие файлы править heredoc'ом в `/tmp` плюс `diff -u` перед `cp`. Перед любым `sed -i` смотреть текущее состояние через `grep -n`. Откат — `git checkout -- файл` и повторный `cp` из `/tmp`.
8. **[2026-07-28] Прод собирается в Docker; правка на хосте не видна без пересборки**
   Симптом: `frontend/.next` на хосте отсутствует, `find / -name robots.txt` находит файл только в слоях overlayfs. `robots.txt` в `.next/server/app/` — это директория с `route.js`, `cat` по ней даёт «Is a directory», и пустой вывод легко принять за отсутствие маршрута.
   Do instead: деплой — `docker compose build frontend && docker compose up -d frontend`. Сервисы `db`, `backend`, `frontend`; контейнер `dao64_frontend`, порт 127.0.0.1:3000. `robots.txt` и `sitemap.xml` генерируются из `src/app/robots.ts` и `src/app/sitemap.ts`; в `public/` из текстовых файлов только `llms.txt`.

9. **[2026-07-28] `git log` печатает время в зоне автора — сравнивать без приведения к UTC нельзя**
   Симптом: `679ad4e` датирован `Sat Jun 27 08:48:34 +0800`, `b18040d` — `Sat Jun 27 15:52:14 +0000`. Визуально первый выглядит «тот же день, раньше», и вывод «черновик новее редизайна» напрашивается сам. В UTC разрыв 15 часов в обратную сторону: 00:48 против 15:52. Цена ошибки — удаление ветки с 1546 строками как якобы устаревшей.
   Do instead: даты коммитов сравнивать только в одной зоне: `TZ=UTC git log -1 --date=iso-local --format="%ad %h %s" <ref>`. Голый `%ad` берёт зону автора и для сравнения непригоден. Для порядка событий брать дату коммиттера `%cd` или `git log --date-order`, а не дату автора: при cherry-pick и rebase они расходятся.

10. **[2026-07-28] Уборка диска: смотреть `docker system df`, а не `du /var/lib/docker`**
   Симптом: диск занят на 40%, `du -xh /var/lib/docker` показывает 277 M и уводит в сторону. Реальные 11 G лежат в `/var/lib/containerd/io.containerd.snapshotter.v1.overlayfs/snapshots` — Docker работает через containerd-снапшоттер. `docker system df` при этом честно показывал Build Cache 7.0 G из 10.2 G образов.
   Do instead: порядок уборки — `docker builder prune -f` (снимает только неиспользуемое, здесь 3.767 G) → `journalctl --vacuum-size=50M` (145 M) → `apt-get clean` (125 M). Итог прохода: 40% → 25%, контейнеры и тома не затрагиваются. Не трогать `/var/lib/mysql` — база FastPanel.

Метод 1 и Метод 3 расходятся раскладкой, но не правилом: у М1 объект диагностики это функция компании, у М3 направление бизнеса. Один метод, один объект; внутри одной гексаграммы объекты не смешивать.

Не объяснять состояние пары линий позиционной уместностью: она даёт три класса на четыре состояния, Ян+Ян и Инь+Инь получают одинаковый статус. Подробно: `64dao_line_semantics_adr.md`.

## [2026-08-16] Передача правок в консоль сервера

**Длинный heredoc при вставке в консоль теряет пустые строки.** Скрипт
на 212 строк с 35 пустыми пришёл с другой суммой. Для замен, внутри
которых есть пустая строка, это фатально: искомый фрагмент не найдётся,
и правка молча не применится. Считать `md5sum` до запуска, а не после.

**Обход — base64 частями с посуммной сверкой.** У base64 нет пустых строк,
кавычек и кириллицы, длина строки 76. Резать на части по 30–40 строк
(`split -n l/4 -d`), у каждой своя сумма: испорченная часть находится
сразу, без построчной сверки. Ловушка 15 августа была не про base64,
а про то, что сверяли число строк вместо суммы.

**`seed_m3.seed_content` перетирает правки из админки.** `title`, `body`
и `mistake` переписываются при каждом прогоне. `seed_m3_zone_reduced`
наоборот пропускает существующие строки. Меняя текст зоны: править seed
и базу, на админку не полагаться.

**Тест может проходить по другой причине, чем обещает имя.**
`test_too_few_rejected` подавал два направления и ждал 422. Счётчик их
не отбивал никогда (`objects_min` равен единице) — отбивал `MIN_COVERAGE`
через доли 45 и 30. Снятие постороннего правила подлог обнажило. Смотреть,
каким именно правилом падает тест, а не только что он падает.


## [2026-08-17] Методика 64DAO: перенос патчей, лимитер в тестах, fixed внутри header

**Base64 частями через FastPanel-консоль не доезжает.** Шесть блоков по 3600
символов дали файл в 18000 байт вместо 21524 и чужую сумму: ровно пять блоков
из шести. Какой именно потерялся — установить не удалось, потому что консоль
не показывала вывод после вставок, а `printf` сам ничего не печатает. Рецепт
от 16 августа («base64 частями с посуммной сверкой») работает только там, где
видно вывод каждой части; здесь этого условия не было.
Do instead: переносить через secret gist + `curl -fsSL 'raw_url' -o файл`
и одну `md5sum`. Одна команда вместо шести, сверка не по частям, а по целому.
Порог простой: всё, что больше пары килобайт, — через gist.

**Миграцию запускать до рестарта бэкенда, а не после.** Код смонтирован с
хоста, поэтому файл миграции виден контейнеру сразу после `git apply`, а
процесс приложения ещё держит старые модели. Порядок «патч → alembic upgrade
→ restart» не оставляет окна, где новые модели встречают старую схему.
Обратный порядок это окно создаёт.

**Лимитер 5/мин валит наборы тестов, а не эндпоинт.** slowapi ключуется по IP,
у всех тестов он один — 127.0.0.1. Шестой POST в файле получал 429, и четыре
падения выглядели как поломка ручки. Подгонять число запросов под потолок
бессмысленно: следующий добавленный тест снова упрётся в невидимую границу.
Do instead: автофикстура `limiter.enabled = False` на весь файл, а сам факт
наличия лимита проверять отдельным тестом со своим `x-real-ip` — тогда он не
зависит от порядка выполнения.

**`backdrop-filter` создаёт containing block для `position: fixed`.**
У `SiteNav` он есть, и модалка, отрендеренная внутри `<header>`, прижалась бы
к высоте шапки вместо всего экрана. Ловится только глазами, `tsc` и сборка
молчат. Do instead: оверлеи рендерить соседом хедера через фрагмент, а не
внутри него. То же касается любых предков с `transform`, `filter`,
`will-change`.

**Файл для письма брать из того же хранилища, что и HTTP-выдача.**
`send_sample_report_email` держала зашитый путь `uploads/sample_report.pdf`,
поэтому запрос примера Метода 3 приходил письмом с примером Методов 1-2.
Расхождение прожило до тех пор, пока документов не стало три.
Do instead: путь к файлу — всегда через `sample_report_store.file_for(method)`,
константы в других модулях не заводить.

**`grep -c` считает строки, а не вхождения.** На минифицированном HTML лендинга
любой счётчик даёт 1, и проверка «кнопка отрисовалась дважды» становится
бессмысленной. Do instead: `grep -o 'строка' файл | wc -l`.

**Оборванная кавычка вешает консоль на `>`.** Дважды за сессию: потерянная
открывающая кавычка при вставке URL и лишний пробел внутри кавычек
(`curl: (3) Malformed input to a URL function`). Do instead: увидев `>` вместо
`$`, нажать Ctrl+C и вставить команду заново целиком — досылать закрывающую
кавычку не надо, в буфер уже попал мусор.

**Документы лендинга: три слота, один механизм.** `sample_report_store` знает
`m12`, `m3` и `methodology`; номер метода из query приводится к коду продукта
через `product_for`, неизвестное значение падает в `m12`. Форма сбора контактов
одна на все три кнопки, документ выбирается параметром `method`.
Лид сохраняется даже если PDF ещё не загружен — эндпоинт отвечает
`pdf_url: null`, форма показывает «контакты сохранены». Раньше на этом месте
открывалась вкладка с 404.
