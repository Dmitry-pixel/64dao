# Спецификация и план реализации: маршрут перехода (роадмап 2.1)

Исполнитель: Claude в репозитории `Dmitry-pixel/64dao`.
Зависимость: реализуется поверх плана мультиконтурной диагностики (`64dao_contours_block_plan.md`), этапы 1–5. Рекомендуемое место в очереди — сразу после этапа 5 (отчёт с контурными секциями и сводной картой).

---

## 0. Зафиксированные решения

1. **Маршрут строится только для контуров.** Базовая пара ЖЦ (6 бинарных вопросов → целевая по карте `_TARGET_HEXAGRAM`) не меняется: её линии — типологические факты, пошаговая смена линий там методологически некорректна; переход остаётся текстовым описанием (`transition_description`).
2. **Порядок шагов внутри контура**: подвижные линии в последовательности — сначала все «старый Инь» (назревшие слабости), затем все «старый Ян» (риски перегрева); внутри каждой группы — снизу вверх (по номеру линии). Согласуется с сортировкой приоритетов, уже принятой в финблоке.
3. **Сводный маршрут компании** (при ≥2 пройденных контурах): этап 1 — контур-ограничение (минимальный `maturity_index`), далее контуры по возрастанию зрелости.
4. **Хранение не меняется**: маршрут — детерминированная функция от снимка `result` контура, вычисляется при генерации отчёта. Миграций нет; воспроизводимость обеспечена снимком.
5. **Новый контент не требуется**: шаги собираются из существующих пакетов действий (слой E, `fin_content`) и `fin_pattern_essence` / `fin_pattern_mistake` (`strategies`). Отсутствующий контент → существующий паттерн «Не заполнено».

## 1. Алгоритм маршрута контура

Вход: `result.lines` (снимок скоринга контура).

```
moving = lines where moving == true
order  = sort(moving): state == 'old_yin' раньше 'old_yang';
         внутри группы — по номеру линии (снизу вверх)

code = combination_current
steps = []
for line in order:
    code = flip(code, line)          # A↔B в позиции линии
    steps.append({
        order:          порядковый номер шага,
        line:           номер линии,
        line_key:       processes|systems|team|leadership|environment|strategy,
        from_state:     old_yin | old_yang,
        action_key:     'line{N}_yin' | 'line{N}_oldyang',   # ключ пакета действий (слой E)
        hexagram_after: {code, number, name}                  # по HEXAGRAM_LIST
    })
```

Инварианты (проверять тестом):

- `steps[-1].hexagram_after.code == combination_resulting` — маршрут всегда приводит в результирующую гексаграмму;
- число шагов = число подвижных линий;
- 0 подвижных → маршрута нет (существующий текст «конфигурация стабильна»);
- 1 подвижная → маршрут из одного шага, без промежуточных состояний.

### Сборка контента шага

| Элемент шага | Источник |
|---|---|
| Заголовок | Название линии (`BLOCKS[N].title` контура) + направление (укрепить Инь / стабилизировать Ян) |
| Что делать | Пакет действий `action_key` из `fin_content` (контурное переопределение → общий, по правилу fallback) |
| Состояние после шага | `fin_pattern_essence` стратегии по `hexagram_after.code` |
| Предостережение (только финальный шаг) | `fin_pattern_mistake` стратегии по результирующей комбинации |

Обязательная оговорка в начале секции (статический текст): последовательность — рекомендуемая логика проработки, а не жёсткое предписание; темп и параллельность шагов определяются ресурсами компании.

## 2. Сводный маршрут компании

Условия и правила:

- Выводится при ≥2 пройденных контурах, в составе раздела «Сводная карта».
- Порядок этапов: `maturity_index` по возрастанию. Тай-брейк 1: больше подвижных линий — раньше. Тай-брейк 2: фиксированный порядок (finance, product, market, process).
- Этап = контур: название, текущая → результирующая гексаграммы (мини-SVG), число шагов, первая подвижная линия как «точка входа». Полный маршрут — в секции контура (ссылка/якорь, в PDF — номер раздела).
- Контуры без подвижных линий в маршрут не включаются; перечисляются строкой «стабильные контуры».
- Если разрыв `maturity_index` между ограничением и следующим контуром ≥3 — акцент: «рекомендуется сфокусировать ресурсы на этапе 1; остальные контуры — в поддерживающем режиме».

## 3. Backend

- Новый модуль `app/contour_route.py`: `build_route(lines: list[dict], combination_current: str) -> list[Step]` и `build_summary_route(contour_results: dict) -> SummaryRoute`. Чистые функции без БД и FastAPI — тестируются изолированно (по образцу `finance_scoring`/`finance_interpret`).
- Рендер: `_contour_section_html` — подраздел «Траектория» расширяется до «Маршрут перехода» (цепочка SVG-гексаграмм: текущая → промежуточные → результирующая, шаги списком); сводная карта — блок сводного маршрута.
- API не меняется: маршрут — часть данных отчёта, отдельный endpoint не нужен.

## 4. Тесты

1. Контрольный кейс финблока (Спецификация §3.7): одна подвижная линия 6 (старый Инь) → маршрут из 1 шага, `hexagram_after` = № 14, совпадает с результирующей.
2. Синтетический кейс: подвижные — линия 2 (старый Ян), линии 1 и 5 (старый Инь) → порядок шагов 1 → 5 → 2; промежуточные коды корректны; финал = результирующая.
3. 0 подвижных → маршрут отсутствует, секция выводит «конфигурация стабильна».
4. 6 подвижных → 6 шагов, вёрстка не ломается (фикстурный рендер).
5. Сводный маршрут: 2 и 4 контура; тай-брейки; правило разрыва ≥3; контур без подвижных линий исключён из этапов.
6. Fallback контента: отсутствующий `fin_pattern_essence` промежуточной гексаграммы → «Не заполнено», рендер без ошибок.
7. Регресс: отчёты без контуров и legacy-отчёты не затронуты.

## 5. Порядок работ (2 PR)

1. **PR 1 — логика**: `contour_route.py` + юнит-тесты (без UI, полностью проверяемо).
2. **PR 2 — рендер**: секция «Маршрут перехода» в контурных секциях HTML/PDF + сводный маршрут в сводной карте + фикстурные рендеры.

Оценка: заметно меньше плана контуров — нет миграций, API и фронтовых флоу; вся работа в логике и рендере отчёта.

## 6. Риски

| Риск | Уровень | Митигация |
|---|---|---|
| Промежуточные гексаграммы попадают на незаполненные `strategies` (№ 43–64 без `fin_pattern_*`) | Средний | Плейсхолдер не ломает отчёт; маршруты повышают приоритет заполнения контента 43–64 — существующий долг, передать владельцу список |
| Длинные маршруты (5–6 шагов) в PDF | Низкий | `page-break-inside: avoid` на карточке шага; фикстурный рендер кейса с 6 шагами |
| Восприятие маршрута как жёсткого предписания | Низкий | Обязательная оговорка в начале секции (п. 1) |

## 7. Вне скоупа (зафиксировано)

- AI-детализация шагов под компанию — роадмап 2.2 (v2), поверх той же структуры.
