## 2. Раздел «Три уровня» (Метод 1)

Разрез шести линий контура по парам: Земля (1,2), Человек (3,4), Небо (5,6).
Новых вопросов нет, миграции данных нет: уровни детерминированы полем `lines`,
которое уже лежит в снимке.

- Расчёт: `app/contour_levels.py`, чистые функции.
- Тексты: `app/level_state_texts.py`, заливка `seed_level_states.py`,
  хранение `fin_content` kind `level_state`, 12 записей.
- Рендер: `finance_interpret` кладёт `levels` и `levels_caveat` в интерпретацию,
  оба отчёта берут готовое.
- Сводная карта: матрица «контуры x уровни», `contour_summary._levels_matrix`.

**Соответствие символов ярлыкам отличается от исходного документа «Business
State Diagnostic».** Там символ означал режим работы, здесь — балл линии выше
порога 2.50, то есть зрелость. При зрелостной шкале Инь+Инь нельзя называть
накоплением, поэтому Импульс и Развитие поменялись местами. Не переигрывать
без разговора: разбор в `64dao_levels_block_plan.md` §2.2.

**Пороги в матрице уровней асимметричны намеренно.** Слабость системна с трёх
контуров или при полном совпадении, опора — только при полном. На живых данных
порог «три из четырёх» для опоры давал три одинаковых вывода, пересказывающих
контур-ограничение. Охраняется тестом `test_support_requires_all_contours`.

## 3. Сокращённый режим Метода 3

Диагностика проходит при одном и двух направлениях. Портфельный слой не
считается, а не подменяется вырожденным.

- `objects_min: 1`, новый `portfolio_min: 3` в `m3_config`.
- `reduced = n < portfolio_min`, считается в `m3_scoring.score_portfolio`,
  хранится в `m3_portfolio_results.reduced` (миграция 035).
- Ниже порога отключены: `UNIFORM_PORTFOLIO`, `SELF_INFLATION`, `RANK_MISMATCH`,
  spearman. Все три флага меряют разброс между направлениями.
- `build_report` подавляет `yin_table`, `constraints`, `metrics`, `tact_note`,
  `rank_comparison`.
- `m3_pdf` глушит разделы 03 и 04 **отдельным заслоном**, см. §5.
- Оговорка едет первой строкой `disclaimers`, оба отчёта её уже печатают.
- Предупреждение перед анкетой: `GET /api/m3/limits`, текст в
  `m3_config.REDUCED_WARNING`.
- Вердикты: `VERDICTS_REDUCED` в `m3_verdict`, пять ключей из двадцати восьми.

Основание отказа от BCG и почему GE работает с одним направлением:
`64dao_m3_reduced_mode_plan.md` §1. Коротко: обе оси GE — абсолютные индексы
по собственным критериям направления, сравнение в их определении не участвует.

## 4. Что осталось

По убыванию важности.

### 4.1 Тексты зон под одиночный режим

Две зоны из девяти прямо ссылаются на портфель и в одиночном отчёте лгут:

- `high_low` «Сбор урожая»: «источник денег для остального портфеля»;
- `mid_high` «Незавершённое ядро»: «останется одним из».

Остальные семь читаются нормально.

Решение принято, не реализовано: вид `zone_reduced` в `m3_content` с откатом
к `zone`, по образцу контурного переопределения в `fin_content`.

Требуется: миграция 036 (ограничение `chk_m3_content_kind` сейчас допускает
только `zone`, `weak_line`, `strong_line`, `tension`), резолюция с откатом
в месте загрузки контента, две строки контента.

### 4.2 Пропуск шага `Р*` при одном направлении

Блок `Р` задаёт рынок на уровне портфеля, `Р*` переопределяет его на уровне
направления. При одном направлении уровни совпадают, и пользователь дважды
отвечает на одно и то же: шесть лишних вопросов.

Важно: пропуск привязан к числу направлений, равному единице, а не к флагу
`reduced`. При двух направлениях уровни уже различимы и шаг нужен. Это
единственное место, где одно и два ведут себя по-разному.

### 4.3 Цена сокращённого отчёта

Не решено владельцем. Отчёт заметно короче полного.

### 4.4 `PROJECT_STATUS.md` устарел

## 5. Ловушки, найденные в эту сессию

**Консоль портит вставки длиннее ~3000 символов.** Это тот же дефект, что
записан в `napkin.md` пункт 5, и он повторился трижды. Heredoc на 160 строк
потерял пять строк молча; base64 на 48 строк развалился целиком. Рабочий приём:
резать по 12 строк base64 или по 1700 символов текста и сверять md5 каждого
куска. Питоновские патчи с длинными строками раздувают блок сильнее, чем
кажется: 34 строки TSX это 1700 символов, а та же вставка в обёртке из Python
уже 3400 и не проходит.

**Эхо консоли срезает первый символ у чисел.** «18 passed» прочиталось как
«8 passed», и я едва не пошёл искать пропавшие тесты. Любое число из вывода
перепроверять отдельной командой.

**`m3_pdf` не читает payload отчёта.** Разделы 03, 04 и вердикты он собирает
сам, вызывая `m3_portfolio` и `m3_verdict` напрямую. Подавление в `build_report`
на PDF не влияет. Тест паритета этого не ловит: он сверяет вердикты и
траектории, а разделы 03 и 04 через него не проходят. Если будете убирать
«лишний» заслон в `m3_pdf` — не убирайте.

**Признак `reduced` ездит на словаре результата.** `verdict_for` зовут из трёх
мест; флаг ставится в `enrich_result` на сам `item`, и все три видят его без
правки сигнатур. Тот же приём используют `cell_breakdown` и `market_label`.

**Ad-hoc скрипты внутри контейнера требуют `import app.models`.** Без него
SQLAlchemy не находит таблицу `orders` и падает на flush с
`NoReferencedTableError`. Импорт только `m3_models` недостаточен.

**Проверка полного режима на проде делается пересчётом в откаченной
транзакции.** Скрипт в §6. Боевой снимок при этом не меняется.

**`CLAUDE.md` был неправ про source volume.** Исправлено: `./backend:/app`
смонтирован, после правки `.py` нужен `restart`, не пересборка. Фронт наоборот,
всегда `build --no-cache` с `NEXT_PUBLIC_API_URL`.

## 6. Эталон полного режима Метода 3

Контрольный портфель: `df86f081-35d4-42bd-a1bd-6bbf179cadbe`, пять направлений.

- Хеш объектного слоя: `e1eb620018fa6a559402122dd52c28dd`
- Портфельный слой: `10 | 9 | 5 | 3 | -0.60 | ["RANK_MISMATCH"] | f`
  (sum_positions, turbulence, delta, distinct_cells, spearman, flags, verdicts_held)

Проверка после любой правки расчёта: пересчитать в транзакции и откатить.

````python
# docker compose exec -T backend python3 - <<'PY'
import asyncio
from sqlalchemy import select, text
from sqlalchemy.orm import selectinload
from app.db import AsyncSessionLocal
import app.models          # обязателен, иначе NoReferencedTableError
import app.m3_models
from app.m3_models import M3Portfolio
from app import m3_service

PID = "df86f081-35d4-42bd-a1bd-6bbf179cadbe"
H = text("""
SELECT md5(string_agg(
  concat_ws(':', object_id::text, symbols, cell_strength, cell_attract,
            coord_strength, coord_attract, current_hex, target_hex, risk_hex,
            v_index, z_index, v_rank, z_rank), '|' ORDER BY object_id::text))
FROM m3_results WHERE portfolio_id = :pid
""")

async def main():
    async with AsyncSessionLocal() as db:
        before = await db.scalar(H, {"pid": PID})
        p = await db.scalar(select(M3Portfolio)
                            .options(selectinload(M3Portfolio.objects))
                            .where(M3Portfolio.id == PID))
        try:
            await m3_service.calculate(db, p)
            print("совпало:", await db.scalar(H, {"pid": PID}) == before)
        finally:
            await db.rollback()
asyncio.run(main())
````

Замер PDF Метода 1: `/root/measure_m1.py` (страницы и высота блока под каждым
заголовком против полосы набора 1010). Для Метода 3 остаются `/root/measure.py`
и `/root/measure3.py`.

## 7. Продуктовые решения этой сессии

Принято владельцем, не переигрывать без разговора.

1. Раскладка линий по бизнес-функциям (предложенный Метод 4) отклонена:
   нарушает ось контроля. `64dao_line_semantics_adr.md` §3.
2. Лидерская типология из четырёх типов не делается.
3. И3 (уровни) к Методу 3 не применяется. ADR §3.1.
4. Свод уровней по компании не делается: уровень компании занят
   `company_lifecycle`. Вместо него матрица «контуры x уровни».
5. Двенадцать текстов состояний уровней оставлены как есть.
6. Номера разделов выводятся, нумерация сквозная, верхние разделы плашкой.
7. Раздел 02 называется «Сценарий стратагемы» в обоих отчётах.
8. Минимум для полного режима Метода 3 остаётся три направления; ниже —
   сокращённый режим, а не отказ.
