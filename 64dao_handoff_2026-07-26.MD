## 0. Как работать в этой сессии

Владелец выполняет команды в браузерной консоли FastPanel на сервере
`root@188.225.77.18`, путь `/var/www/64dao`, и вставляет вывод обратно. Одна
команда за раз, ждать приглашения.

**Правила доставки правок, выведенные из ошибок этой сессии:**

- Правки существующих файлов — только через `python3 -c` с `assert` на число
  вхождений и `compile()` перед записью. Никогда без проверок.
- Новые файлы — через `nano -w <путь>` со вставкой содержимого, затем
  `python3 -m py_compile` для контроля.
- **`.env` в редакторе не открывать.** Дважды получили склейку соседних строк
  с отложенным падением. Только точечная замена через `python3 -c`.
- Вывод в консоли затирается при прокрутке. Запрашивать по одному файлу,
  держать вывод в пределах 20–30 строк.

**Правила деплоя:**

- Бэкенд: `docker compose build backend && docker compose up -d backend`.
  `restart` не подхватывает ни код, ни `.env`.
- Фронтенд: `docker compose build --build-arg NEXT_PUBLIC_API_URL=https://64dao.ru frontend && docker compose up -d frontend`.
- Миграции: `docker exec dao64_backend alembic upgrade head`. По правилу
  проекта миграция должна попасть в origin **до** применения на проде. В этой
  сессии правило дважды нарушено, оба раза без последствий, но повторять не надо.
- Тесты: `docker compose exec -T backend python -m pytest tests/<файл>.py -q`,
  по одному файлу.

## 4. Открытые хвосты и предупреждения

**Пароль базы данных засветился в переписке** при разборе повреждённого `.env`.
База слушает только внутреннюю сеть Docker, наружу не торчит, но пароль надо
сменить: роль в PostgreSQL, затем `DB_PASS` в `backend/.env`, затем
`docker compose up -d backend`. Роль называется `dao64`, не `dao`.

**Отправитель писем.** Timeweb разрешает ставить в `From` только адрес
аутентифицированного ящика: отправка как `support@` или `admin@` под логином
`noreply@` отбивается с `550 5.7.1`. Механизм привязки адреса к шаблону в коде
есть и защищён списком `SMTP_SENDERS`, но список состоит из одного адреса,
и выбор в интерфейсе не сделан. Чтобы включить — нужны отдельные SMTP-доступы
на каждый ящик и переработка отправки.

**Пароль SMTP был просрочен**, отправка почты не работала неизвестно сколько.
Не всплывало, потому что писем к отправке не было. Перед запуском с клиентами
проверку отправки надо включить в приёмку.

**Лишняя запись от 26.07** в кабинете: повтор, созданный до исправления
связывания у админа. Числится второй первичной диагностикой. Удалить кнопкой
«Удалить» и пройти повтор заново.

**Поиск не синхронизирован с адресной строкой.** Ссылку с результатом переслать
нельзя. Правка небольшая, но тянет обработку истории браузера.

**Клиентов на проде нет, все диагностики тестовые.** Это окно для структурных
изменений; оно закроется с первым платящим клиентом.
